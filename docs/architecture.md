# Устройство движка

## Модули

| Файл | Что делает |
|---|---|
| `src/main.c` | подъём оборудования, загрузка общих данных, главный цикл, мигание кодом ошибки |
| `src/vm.c` | интерпретатор байткода сценария, отрисовка сцены, экраны сохранений и галереи, эффекты |
| `src/gfx.c` | двойная буферизация, загрузка TIM в слоты видеопамяти, спрайты, прямоугольники, шрифт |
| `src/cd.c` | подъём привода, чтение файлов, общий файл картинок |
| `src/seq.c` | банк VAB, секвенсор SEQ, звуковые эффекты |
| `src/voice.c` | озвучка из общего файла XA |
| `src/str.c` | видео STR через MDEC |
| `src/save.c` | таблица глав, формирование и проверка записи сохранения |
| `src/card.c` | карта памяти: файл сохранения, слоты, глобальный кадр |
| `src/gallery.c` | таблица галереи и признаки открытых сцен |
| `src/pad.c` | геймпад |
| `src/vn.h` | общие объявления, слоты видеопамяти, режим релиза |

## Запуск

```
gfx_init          видеорежим, двойной буфер
cd_init           привод: Nop, чтение оглавления, режим 2048 байт, до 6 попыток
pad_init
InitGeom, SpuInit GTE для видео, звуковой процессор
cd_load SYSTEM.CNF  пробное чтение: оглавление доступно целиком
cd_pak_open       указатель общего файла картинок
voice_open        указатель озвучки (если есть)
save_load_chapters  таблица глав
card_init         драйвер карты НЕ поднимается: это при первом обращении
card_load_header  заголовок сохранения с иконкой и именем файла
gal_load_table    таблица галереи (признаки с карты — позже)
FONT.TIM, FONT.WID
seq_load_bank     банк инструментов
vm_start          первая глава сценария
```

Драйвер карты памяти и признаки галереи откладываются до первого
обращения: игрок может ни разу не сохраниться, а на некоторых платформах
подъём драйвера на старте подвешивает игру.

## Главный цикл

Шестьдесят раз в секунду:

```c
voice_tick();   // счётчик длительности реплики
seq_tick();     // такт секвенсора музыки
vm_update();    // ввод и шаг сценария
vm_render();    // сцена в список примитивов
gfx_flip();     // ожидание кадра, смена буферов
```

## Чтение с диска

`cd_load_to()` ищет файл по каталогу, читает его целиком и ждёт конца
чтения **опросом раз в кадр**. Между опросами вызывается такт секвенсора,
поэтому музыка не замирает на загрузках.

Почему именно раз в кадр: документация PSn00bSDK требует периодического, а
не сплошного опроса. Плотный цикл не давал отработать обработчику
прерывания привода, и чтение не завершалось никогда.

Ошибка чтения повторяется до четырёх раз; одно ожидание ограничено
десятью секундами, после чего чтение считается неудачным, а не вечным.

Картинки читаются из общего файла `ART.PAK` по номеру сектора, без поиска
по каталогу.

## Интерпретатор

Сценарий компилируется в байткод (опкоды — в [formats.md](formats.md)) и
режется на главы до 96 КБ. В памяти живёт одна глава; переход в другую
подгружает её с диска. Адрес перехода — `(глава << 24) | смещение`.

Состояния интерпретатора:

| Состояние | Что происходит |
|---|---|
| `S_RUN` | выполняются опкоды подряд, до первого ожидающего |
| `S_TEXT` | реплика печатается и ждёт нажатия |
| `S_WAIT` | пауза `wait` |
| `S_FADE` | затемнение или проявление |
| `S_CHOICE` | выбор игрока |
| `S_SPLASH` | заставка |
| `S_MENU` | титульное меню |
| `S_END` | конец сценария |

Экраны сохранения, загрузки и галереи, пока открыты, забирают ввод целиком,
чтобы крестик не пролистывал реплики за их спиной.

## Графика

Экран 320×240, два кадровых буфера в видеопамяти: `(0,0)` и `(0,240)`.
Каждая картинка загружается в свой **слот** видеопамяти и рисуется
спрайтом; общий счётчик слотов не ведётся, каждый вид картинки занимает
заранее отведённое место.

| Слот | Положение (полуслова) | Размер | Палитра |
|---|---|---|---|
| фон | 320, 0 | 160×240 (320 пикс. 8 бит) | 0, 480 |
| персонаж 0 | 512, 0 | 128×256 | 0, 481 |
| персонаж 1 | 640, 0 | 128×256 | 0, 482 |
| персонаж 2 | 768, 0 | 128×256 | 0, 483 |
| персонаж 3 | 896, 0 | 128×256 | 0, 485 |
| шрифт | 320, 256 | 64×198 (4 бита) | 0, 484 |
| кадры сцены 0–3 | 384…864, 256 | 160×240 каждый | 0, 496…499 |

Видеопамять занята почти полностью, свободных крупных участков нет.

**Порядок отрисовки.** Внутри одного слоя списка примитивов добавленный
последним рисуется первым, то есть оказывается снизу. Поэтому подложку
нужно добавлять после того, что лежит на ней. Персонаж в слоте 0
оказывается поверх остальных.

**Тряска** сдвигает не картинку, а показываемую область видеопамяти: дрожит
весь экран разом, и это ничего не стоит.

## Звук

Звуковой процессор, 24 голоса:

| Голоса | Назначение |
|---|---|
| 0–19 | музыка (SEQ) |
| 20–23 | звуковые эффекты, по кругу |

Банк инструментов загружается в звуковую память при старте. Сэмплы
тянущихся инструментов зациклены флагами в самих данных ADPCM.

Озвучка XA идёт отдельным путём: привод отдаёт аудиосекторы прямо в
звуковой процессор, фильтр выбирает канал нужной реплики. Музыка при этом
продолжает играть.

## Видео

STR читается в кольцевой буфер на 128 секторов, кадры собираются из
секторов вне прерывания и декодируются аппаратным MDEC. Конец ролика
определяется по счётчику кадров и по сбросу номера кадра. После ролика
кадровые буферы затёрты, поэтому сценарий ставит фон заново.

## Сохранения

Сохраняются только **на границе главы**: глава обязана выстроить сцену с
нуля, поэтому для восстановления хватает номера главы и флагов. Не нужно
сериализовать ни экран, ни спрайты, ни состояние интерпретатора.

Глава обозначается **хешем названия**: вставка новой главы в середину
сценария не ломает старые сохранения. Запись дополнительно несёт отпечаток
сборки — после пересборки сценария с другими главами старое сохранение
честно отвергается.

На карте памяти — один файл в один блок: заголовок с иконкой, четыре слота
и кадр с признаками галереи. Работа идёт через файловые вызовы BIOS
(`bu00:`); низкоуровневые вызовы оставлены запасным путём. После записи
файл перечитывается, чтобы «сохранено» было фактом, а не обещанием.

## Память

Основные статические буферы:

| Буфер | Модуль | Размер |
|---|---|---|
| банк инструментов | seq.c | 288 КБ |
| кольцо секторов видео | str.c | 256 КБ |
| трек SEQ | seq.c | 128 КБ |
| временный буфер чтения | cd.c | 128 КБ |
| поток и вывод MDEC | str.c | 2 × 128 КБ |
| указатель озвучки | voice.c | 96 КБ |
| глава сценария | main.c | 96 КБ |
| шрифт | main.c | 40 КБ |

Всего около 1.35 МБ из 2 МБ, остальное — код, стек и мелкие таблицы.
Сборка данных сверяет каждый файл с размером его буфера и отказывается
собирать, если не влезет.

## Режим релиза

Макрос `VN_RELEASE` (ключ CMake `-DVN_RELEASE=ON`) превращает `LOG(...)` в
пустое место и убирает отладочный оверлей. Мигание кодом при фатальной
ошибке остаётся.
