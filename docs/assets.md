# Ассеты

Всё, что попадает на диск, лежит в репозитории в обычных форматах: PNG,
MIDI, WAV. Сборка данных (`tools/build_data.py`) сама переводит их в
форматы приставки. Руками ничего конвертировать не нужно.

## Картинки

```
art/bg/<имя>.png                  фоны               -> bg <имя>
art/char/<кто>/<эмоция>.png       персонажи          -> char N <кто>/<эмоция> x y
art/scene/<имя>/<кадр>.png        анимированный фон  -> scene <имя>
```

Имена файлов и папок становятся именами в сценарии. Номера не нужны:
сборка сама нумерует картинки, и вставка новой в середину ничего не ломает.

| Вид | Размер | Цвет | Примечание |
|---|---|---|---|
| фон | 320×240 | 256 цветов | больший размер вписывается автоматически |
| персонаж | до 256×256 | 256 цветов + мягкий край | прозрачность из альфа-канала PNG |
| кадр сцены | 320×240 | 256 цветов | до четырёх кадров, по алфавиту |

**Мягкий край.** У персонажей полупрозрачные пиксели по контуру (волосы,
сглаживание) получают третий уровень прозрачности через бит STP. Полностью
прозрачное становится прозрачным, полностью непрозрачное — непрозрачным,
промежуточное — смешивается с фоном пополам. Так край не рвётся и не
обрастает ореолом.

**Персонаж и экран.** Экран 240 строк. Спрайт попадает в игру без обрезки;
куда его ставить, считается так: `x = центр - ширина/2`, `y = 240 - высота`.
Ширину и высоту сборка печатает для каждого спрайта. Текстовое окно
полупрозрачное, поэтому нижняя часть фигуры не пропадает, а просвечивает.

**Общий файл картинок.** Все картинки складываются в `data/ART.PAK` с
указателем в начале. Поиск по каталогу диска случается один раз при
старте, дальше привод встаёт сразу на нужный сектор. Посмотреть
содержимое: `python3 tools/unpak.py data/ART.PAK`, выгрузить обратно:
`python3 tools/unpak.py data/ART.PAK out/`.

## Шрифт

Шрифт растеризуется при сборке: 162 глифа (латиница, кириллица, Ё/ё) в
ячейках 16×18, 16 уровней серого, с шириной каждого глифа для
пропорционального вывода.

**Длинного тире, ёлочек и многоточия в наборе нет** — в реплике они молча
превращаются в пробелы. Пишите дефис, прямые кавычки и три точки.

## Музыка

`music.txt`:

```
# имя   файл              tick_hz  loop
theme   music/theme.mid   240      loop
```

Имя используется в сценарии: `bgm play theme`. Третья колонка оставлена
для совместимости и не используется. `loop` зацикливает трек.

MIDI переводится в формат SEQ (Psy-Q) и играется секвенсором движка через
звуковой процессор. Музыка не занимает привод, поэтому звучит непрерывно,
даже пока грузятся картинки. Канал 10 (ударные) автоматически переводится
на программу ударных банка.

## Инструменты

Ноты играются сэмплами из банка `data/BGM/BANK.VAB`, который собирается по
`instruments.txt`:

```
# мелодические: номера программ GM, сэмпл, базовая нота
prog 0,2,4,5        piano     60
prog 40,41,42,43    strings   60

# ударные: ноты канала 10, сэмпл, [нота, на которой сэмпл звучит как есть]
drum 35-36          kick      36
drum 42-44          hihat     42

# звуковые эффекты для команды se: имя в сценарии, сэмпл
sfx  click   hihat
sfx  thud    kick
```

Сэмпл берётся из `instruments/<имя>.wav`, а если такого файла нет — из
встроенного синтезатора: `piano`, `epiano`, `marimba`, `guitar`, `bass`,
`lead`, `pad`, `strings`, `organ`, `brass`, `reed`, `flute`, `bell` и
ударные `kick`, `snare`, `hihat`, `hihatopen`, `crash`, `ride`, `clap`,
`tom`, `shaker`, `tamb`.

**Встроенный синтез — заглушка.** Он нужен, чтобы музыка звучала сразу, но
настоящего качества даёт только замена на записи. Тянущиеся инструменты
синтеза (струнные, пэд, орган, медь, язычковые, флейта) зациклены
бесшовно, поэтому длинные ноты не обрываются.

### Записи из свободных SoundFont

`tools/sf2dump.py` достаёт сэмплы из банков формата SF2 вместе с точкой
петли и базовой нотой:

```bash
python3 tools/sf2dump.py TimGM6mb.sf2 --list
python3 tools/sf2dump.py TimGM6mb.sf2 --extract 0  --out instruments/piano.wav
python3 tools/sf2dump.py TimGM6mb.sf2 --extract 48 --out instruments/strings.wav
```

Номер — программа General MIDI. Точка петли сохраняется в WAV и
подхватывается сборкой банка. Ключ `--key` выбирает сэмпл для другой части
клавиатуры.

Свободные банки: TimGM6mb (общественное достояние), Fluid R3 GM и MuseScore
General (MIT), наборы проекта FreePats (CC0 и CC-BY). Перед публикацией
игры проверьте лицензию выбранного банка: CC-BY требует указать автора,
CC-BY-NC запрещает коммерческое использование.

### Ограничения банка

- до 16 тонов на программу;
- тело банка до 288 КБ (буфер в памяти приставки), звуковая память — 512 КБ;
- голоса 0–19 отданы музыке, 20–23 — звуковым эффектам.

## Звуковые эффекты

Объявляются строками `sfx` в `instruments.txt` (см. выше), в сценарии —
`se <имя>`. Играют на своих голосах и не обрывают ноты музыки.

## Озвучка

`voice.txt`:

```
# имя         файл
sylvie_hi     voice/sylvie_hi.wav
```

В сценарии — `voice sylvie_hi`. Нужен `psxavenc`.

Все реплики складываются в один файл `data/VOICE.XAS` с чередованием
каналов: поток 18900 Гц моно занимает каждый шестнадцатый сектор, и в
свободные слоты кладутся другие реплики. Фильтр привода выбирает нужный
канал. Реплики сортируются по длине, чтобы короткие не теряли место рядом
с длинными; на сотнях реплик пустого места остаётся несколько процентов.

| | |
|---|---|
| реплик максимум | 12 286 |
| место на диске | около 38 МБ на час речи |
| качество | 18900 Гц, моно, XA-ADPCM |

Пока звучит реплика, привод занят потоком: загрузка картинки её оборвёт.

## Видео

```bash
python3 tools/encode_video.py intro video/intro_src.mp4
```

Инструмент вызывает `psxavenc`, кладёт результат в `video/intro.str` и
регистрирует его в `videos.txt`. В сценарии — `str intro`.

Параметры по умолчанию: 320×224, 15 кадров в секунду, звук XA 37800 Гц
стерео, поток на двойную скорость привода. При таком разрешении поток
занимает почти всю полосу привода; если ролик заикается, уменьшите
разрешение или частоту кадров. `psxavenc` собирается из исходников
(нужны `meson` и пакеты `libavformat-dev`, `libavcodec-dev`,
`libswscale-dev`, `libswresample-dev`).

### Тестовый ролик

```bash
python3 tools/make_test_video.py
```

Собирает `video/test.str` — десять секунд с крупным номером кадра,
временем, цветными полосами, полосой, пробегающей экран за секунду, и
коротким сигналом в начале каждой секунды (слева на чётных, справа на
нечётных). В демо он открывается пунктом «Видео» титульного меню.

В отладочной сборке после любого ролика на десять секунд выводится его
отчёт — две строки, которые удобно сфотографировать:

```
f147 drop0 dec0 over0 end
cb1286 bad1 m00000000 cd0 oth0
```

| Поле | Что значит |
|---|---|
| `f` | показано кадров |
| `drop` | кадров выброшено (не все секторы кадра успели прийти) |
| `dec` | кадров, которые не разобрал декодер |
| `over` | секторов потеряно: кольцевой буфер переполнился |
| `end` / `skip` / `TIMEOUT` / `CDERR` | чем кончилось: конец файла, пропуск кнопкой, три секунды без кадра, ошибка привода |
| `cb` | сколько секторов данных отдал привод |
| `bad`, `m` | сколько пришло секторов не-видео и сигнатура первого из них |
| `cd`, `oth` | ошибка диска и прочие события привода |

Как читать: `cb0` — привод вообще не отдал данных, дело в команде чтения
или режиме привода; `cb` большое, а `f0` — данные идут, но это не видео
(смотрите `m`); `f` есть, но `dec` растёт — декодер не понимает
битстрим.

## Иконка сохранения и название

`save_icon.png` (или `.ico`) в корне проекта — любая картинка, конвертер
сам ужмёт её до 16×16 в 16 цветах.

`game.txt`:

```
title     THE QUESTION PS1      # название в менеджере карт памяти, латиница
savefile  BASLUS-VNDEMO0001     # имя файла на карте, до 19 символов
volume    VNDEMO                # метка тома диска
```

Придумайте для своей игры собственный код в `savefile`: по нему игра
находит своё сохранение, и у разных игр на одной карте он должен
различаться.

## Импорт из Ren'Py

```bash
python3 tools/import_renpy.py путь/к/игре/game --lang russian --music theme
```

Переводит простую игру Ren'Py в проект движка:

- фоны 16:9 уменьшает до высоты 240 и обрезает по центру до 320×240;
- спрайты уменьшает в той же пропорции, что и экран (720 → 240);
- переводит `script.rpy` в `script/imported.vns`, подставляя реплики из
  перевода `tl/<язык>/script.rpy`, если он указан;
- заменяет символы, которых нет в шрифте;
- печатает всё, что перенести не удалось.

Понимает самое ходовое подмножество Ren'Py: персонажей, метки и
переходы, `scene`, `show`, `hide`, меню, флаги `True`/`False` и условия по
ним, музыку, реплики. Ren'Py — целый язык на Python, поэтому полный перенос
невозможен; результат — отправная точка, которую дорабатывают руками.
Демо-игра этого репозитория получена именно так.
